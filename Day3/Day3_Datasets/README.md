# دیتاست‌های روز سوم

این مجموعه برای تمرین مهندسی API و RAG طراحی شده است. داده‌های کاربران، پرونده‌ها، درخواست‌ها، قیمت‌ها، حمله‌ها و لاگ‌ها کاملاً مصنوعی‌اند. پرونده‌ها دربارهٔ پژوهش فنی نرم‌افزار هستند.

## مجموعه‌ها

- `01_Corpus`: بیست‌وچهار سند واقعی PEP از مخزن رسمی Python؛ نسخه و SHA-256 در manifest ثبت شده است. متن اصلی و بخش مجوز هر سند حفظ شده است.
- `02_Evaluation`: نود پرسش، شامل ۷۲ پرسش پاسخ‌پذیر و ۱۸ پرسش خارج از پوشش؛ ۳۰ پرسش در هر تقسیم. برچسب‌های train/dev ارائه شده‌اند؛ برچسب آزمون در بستهٔ مدرس است.
- `03_Application`: بیست کاربر، ۱۲۰ پروندهٔ پژوهشی و چهار سیاست ساختگی برای مالکیت و تفکیک tenant.
- `04_API`: دو هزار و چهارصد درخواست شبیه‌سازی‌شده، شش سناریوی retry و قیمت‌های کاملاً فرضی برای محاسبهٔ هزینه.
- `05_Router`: چهارصد و هشتاد درخواست در چهار مسیر؛ گروه‌های قالب میان train/dev/test جدا هستند.
- `06_Robustness`: سی حملهٔ مصنوعی و چهار خروجی برای بررسی استناد.
- `07_Observability`: چهار هزار و هشتصد رویداد ساختگی با correlation ID و چند secret آزمایشی برای آزمون حذف اطلاعات حساس.

## منبع و حقوق استفاده

در نسخهٔ r2، فایل `02_Evaluation/queries.jsonl` فقط سه ستون query_id، query و split دارد. شناسه‌ها نام سند یا پاسخ‌پذیری را کد نمی‌کنند و ترتیب سطرهای عمومی مخلوط است. برچسب و خانوادهٔ پرسش فقط برای train/dev در qrels_train_dev آمده‌اند؛ gold کامل در بستهٔ مدرس است. حجم و متن پرسش‌ها نسبت به نسخهٔ قبلی عوض نشده‌اند.

اسناد PEP از https://github.com/python/peps و https://peps.python.org دریافت شده‌اند. مجوز public domain یا CC0 در هر فایل اصلی آمده است. PEPها ممکن است وضعیت‌ها و نسخه‌های تاریخی متفاوت داشته باشند؛ آن‌ها را سند طراحی بخوانید، نه اثبات اینکه هر ویژگی در هر نسخهٔ Python اجرا می‌شود.

فایل‌های آموزشی مصنوعی این بسته برای استفاده و تغییر در همین بوت‌کمپ تهیه شده‌اند. ادعای دادهٔ واقعی، بنچمارک عمومی یا اعتبار تولیدی ندارند.

مدل embedding در `Day3_Resources/embedding_model` جداگانه با نام، نسخه، مجوز و hash بسته‌بندی می‌شود. هیچ credential واقعی در داده‌ها وجود ندارد. `TEST-ONLY-SECRET` فقط fixture آزمون حذف اطلاعات حساس است.
